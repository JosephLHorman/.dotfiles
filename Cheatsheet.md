## Conflicts & Overrides

Things that are shadowed, doubled up, or don't behave the way you'd expect.

| Key | Wins | Loses | Where |
|---|---|---|---|
| `gr` | LSP references (telescope) | nvim 0.12's whole `gr*` family, in any LSP-attached buffer: `grn` rename, `gra` code action, `grr` references, `gri` implementation, `grt` type def, `grx` | `lua/config/autocommands.lua:11` |
| `<C-Space>` | tmux prefix | blink.cmp's "show completion / docs", **and** fzf-tab's multi-select toggle | `tmux/.config/tmux/tmux.conf:7` |
| `<CR>` (normal) | `:noh` + a literal `<CR>` | quickfix / help "jump to entry" — the trailing `<CR>` is non-recursive, so buffer-local `<CR>` maps never fire | `lua/config/keymaps.lua:21` |
| `gc` / `gcc` | mini.comment | nvim 0.12's built-in commenting (identical behavior — pure redundancy) | `lua/plugins/mini.lua:34` |
| `[d` / `]d` | LspAttach remap | nvim 0.12's built-in diagnostic motions (identical behavior — redundancy) | `lua/config/autocommands.lua:16-17` |
| `an` / `in` | mini.ai next-textobject | nvim 0.12's built-in incremental selection | mini.ai (deliberate upstream) |
| `al` / `il` | mini.ai last-textobject | nvim 0.13's line/buffer textobjects (not yet relevant on 0.12) | mini.ai (deliberate upstream) |
| `s` (normal) | nothing — but it now waits | bare `s` (substitute char) stalls for `timeoutlen` because mini.surround owns `sa sd sr sf sF sh` | `lua/plugins/mini.lua:37` |
| `<C-l>` (tmux, no prefix) | vim-tmux-navigator "pane right" | terminal clear-screen — use **`<prefix> C-l`** instead, which the plugin binds for exactly this | vim-tmux-navigator |
| `<C-k>` (insert) | blink.cmp signature help | nvim's built-in digraph entry | `lua/plugins/completion.lua:7` |
| `<prefix> r` *and* `<prefix> R` | both reload tmux.conf | — two live bindings doing the same job (`r` yours, `R` from tmux-sensible) | `tmux.conf:1` + tmux-sensible |
| `<prefix> Space` | `next-layout` (tmux default) | tmux-sensible *wanted* to make this `last-window`, but skips keys tmux already binds — so it never applied. Use `<prefix> l` for last-window. | tmux-sensible |

**Two doc corrections while I was in here** (README `## Keybindings to remember:` — no config change made):

- README:77 says mini.ai's `f`/`c`/`a` become treesitter-aware. They don't in this config —
  no treesitter textobject spec is wired up. `f` is a Lua-pattern *function call*, `a` is an
  argument, and there is no `c` textobject at all.
- README:56-57 describes `m` as single-file rename and `c` as copy-with-rename. Closer to the
  truth: `r` is rename, `m` is move, `c` is copy — `m`/`c` just happen to prompt for a
  destination path, which reads like a rename when one file is selected.
