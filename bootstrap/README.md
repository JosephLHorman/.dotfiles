# Provisioning

Using mise, achieve a more-or-less declarative machine state.
`mise.toml` states what the machine should look like and
`mise bootstrap` converges to it. This directory holds only the parts that
cannot be declared.

```sh
./bootstrap.sh              # fresh machine, nothing installed
mise bootstrap              # thereafter; re-runnable, converges to mise.toml
mise bootstrap --dry-run    # print what would change
mise bootstrap status       # what is and is not in place
mise bootstrap plan         # declarative resource diff
```

Run as your normal user, never root — `$HOME` and file ownership would be
wrong, and sudo is needed only for apt.

## Why bootstrap.sh exists

Exactly one reason: `bin/mise` fetches mise with curl, and a bare Debian or
Ubuntu image has no curl. `bootstrap.sh` refuses root, checks the distro is
Debian-family, installs curl, and execs `bin/mise bootstrap`. Nothing else.

`bin/mise` is generated by `mise generate install-script` and committed. It
downloads a pinned mise on first use, so a fresh machine needs nothing
preinstalled. Regenerate it to move to a newer mise.

## What is declared where

Everything in `mise.toml`, applied in mise's phase order — which is why nothing
declares dependencies:

| Phase | Section | Covers |
|---|---|---|
| 4 | `[bootstrap.packages]` | apt: zsh, tmux, build deps, clipboard |
| 9 | `[bootstrap.repos]` | fzf, TPM |
| 10 | `[dotfiles]` | every symlink into `$HOME` |
| 15 | `[bootstrap.user]` | login shell |
| 16 | `[tools]` *(global config)* | neovim, ripgrep, fd, lazygit, tree-sitter, starship, shellcheck, uv |
| 17 | `[tasks.bootstrap]` | plugin setup — `bootstrap/tasks/bootstrap` |

Ordering falls out for free: dotfiles land before tools, so the global
`config.toml` holding `[tools]` is linked before it is read; and starship is
installed at 16, long before any shell needs it.

`[tools]` lives in `mise/.config/mise/config.toml` rather than `mise.toml`
because the toolchain should be on PATH everywhere, not only inside this
directory.

## What stays imperative

`bootstrap/tasks/bootstrap` — plugin managers that fetch over the network and
binaries compiled locally: fzf's `install --bin`, TPM's `install_plugins`,
nvim's `Lazy! sync` plus treesitter parsers and mason servers, and zinit's
first-run fetch.

# Bootstrap Notes
## Where dependencies are declared

| Layer | Declared in | Contents |
|---|---|---|
| Developer tools | `mise/.config/mise/config.toml` → `[tools]` | neovim, ripgrep, fd, lazygit, tree-sitter, starship, shellcheck, node, uv |
| System packages | `mise.toml` → `[bootstrap.packages]` | zsh, tmux, git, curl, unzip, build-essential, make, luarocks, libreadline-dev, python3-venv, clipboard |
| Git checkouts | `mise.toml` → `[bootstrap.repos]` | fzf, TPM |
| Plugin managers | bootstrapped by the configs themselves | lazy.nvim (`init.lua`), zinit (`.zshrc`), TPM plugins (the `bootstrap` task) |

`mise bootstrap status` reports the installed version of everything, which is
why no version file is committed.

## Non-obvious dependencies

Things whose need is not apparent from the config that requires them:

- **`python3-venv`** — nothing in the nvim config mentions Python, but mason
  builds a venv to install `basedpyright`, and Debian splits `ensurepip` out of
  the base `python3` package. Without it that one server fails while the other
  six succeed.
  is installed through npm by mason.
- **C compiler + `make`** — `telescope-fzf-native` has `build = 'make'`, and
  nvim-treesitter compiles each parser locally.
- **`tree-sitter` CLI** — nvim-treesitter's `main` branch needs it to build
  parsers. No distro packages it.
- **`libreadline-dev`** — luarocks wants it.
- **The `mise activate` line in `.zshrc` is hand-written**, not managed by
  `[bootstrap.mise_shell_activate]`. mise declines to edit a target that is a
  symlink, and `[dotfiles]` symlinks `~/.zshrc` into this repo.
- **`tree-sitter` is version-pinned while every other tool tracks latest.**
  Upstream's prebuilt binary needs GLIBC_2.39 in both 0.25.0 and 0.27.0, but
  Debian 12 ships glibc 2.36 — and since the baseline moved back and forth
  across releases rather than only forward, "latest" cannot be assumed to run
  everywhere. 0.25.10 runs on all supported targets. It is the one tool where
  a version bump needs testing against Debian 12 first.
- **TPM splits across two directories.** It is cloned to `~/.tmux/plugins/tpm`,
  because that is the path the last line of `tmux.conf` runs — but it installs
  the plugins themselves to `~/.config/tmux/plugins/`, next to the XDG config.
  Both are correct; anything checking for an installed plugin has to look in
  the second location, not the first.
- **fzf is a git checkout, not a package.** `.zshrc` sources
  `~/.fzf/shell/*.zsh` directly to avoid `fzf --zsh` forking on every startup,
  and `.zshenv` puts `~/.fzf/bin` on PATH. A packaged fzf does not provide that
  layout, and mise's tool backends ship only the binary. `[bootstrap.repos]`
  clones it; the `bootstrap` task runs `install --bin` afterwards, because
  there are no post-clone hooks.

## Still testing

- **The login shell** is declared (`[bootstrap.user] login_shell`) and needs an
  absolute path, not a command name. Changing it affects future sessions only.
- **`<prefix>I` in tmux** *shouldn't* needed — the `bootstrap` task runs TPM's
  `install_plugins` directly — but it remains the way to install a plugin you
  add later.
- **Windows** is out of scope for mise currently. Starship for PowerShell and 
  a carbonfox theme for Windows Terminal are still open questions in the README TODO.
